# 知识库与RAG

让智能体基于私有知识回答问题。

## RAG 流程

```
用户提问 → 检索知识库 → 拼接 Prompt → 大模型回答
```

## 搭建流程

1. **文档准备**：清洗、统一格式、构造分隔符
2. **文档切割**：语义独立且完整的知识分片
3. **向量化存储**：存储到向量数据库
4. **检索**：匹配相关内容
5. **排序**：粗排 + 精排

## 检索方式

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| 向量检索 | 语义相似度匹配 | 语义相关，**图文混搜推荐** |
| 全文检索 | 关键词精确匹配 | 精确关键词 |
| 混合检索 | 先全文后语义 | 综合效果最好 |

## 排序机制

| 阶段 | 说明 |
|------|------|
| 粗排 | 向量匹配，语义相似度 |
| 精排 | Reranker，更准确但更慢 |
| 多模态精排 | doubao-seed-rerank，可对图文索引重排（v2.5.0+） |

**原因**：文本转向量有信息损失，Reranker 可弥补

## 配置参数

| 参数 | 说明 |
|------|------|
| 调用方式 | 强制模式（必查）/ Auto 模式（智能判断） |
| 检索方式 | 向量/全文/混合 |
| 召回分段数 | 检索多少个段落 |
| 相似度设置 | 阈值越高召回越少 |
| 扩展上下文 | 自动加入前后段落 |
| 无召回回复 | 无命中时的兜底回复 |
| query instruction | 检索指令拼接到query前向量化（v2.3.0+） |

## 标签过滤（v2.5.0+）

| 条件 | 说明 |
|------|------|
| 属于（IN） | 标签值需匹配指定字符串列表中任意一个，逗号分隔 |
| 不属于（NOT IN） | 标签值不能是指定列表中的任何一个，逗号分隔 |

- 标签Key已改为case-sensitive（v2.5.0）

## 支持的文件格式

| 类型 | 格式 | 版本 |
|------|------|------|
| 文档 | Excel、CSV、PDF、WORD、PPT | 初始 |
| 飞书云文档 | 飞书知识库、云盘文件、多维表格 | v2.2.0+ |

## 导入限制

- Excel 文件：约 25M
- 分段行数上限：100（v2.5.0调整）
- Office文件大小上限：可配置，默认50最大100（v2.5.0+）
- 非UTF-8编码：GBK/GB2312/GB18030/ASCII（v2.3.0+）

## 解析服务

| 服务 | 说明 | 版本 |
|------|------|------|
| 内置解析 | 默认解析服务 | 初始 |
| PaddleOCR-VL | PDF解析，效果显著优于其他（需GPU/NPU），强烈推荐 | v2.5.0 |
| VLM解析 | PDF使用VLM解析，业界最优（需GPU） | v2.4.0 |
| Textin解析 | 需自行采购，仅支持私部v3.0.0 API | v2.2.0 |
| 自定义解析 | 通过SDK实现 | v2.2.0 |

### 解析配置

- 切片重叠字数：可配置切片重叠比例（v2.3.0+）
- 按页切分：严格按页码切分，仅PDF/PPT/OFD（v2.3.0+）
- PDF兜底超时：可配置，默认45分钟。`PARSER__PYMUPDF_TIMEOUT="2700"`（v2.5.0）
- PDF高精度解析页数：上限从50调整到500（v2.5.0）
- 解析任务控制：支持单个任务终止和重试（v2.3.0+）
- 重复文件导入：从静默跳过改为显式提醒（v2.4.0+）

## 图文混搜（v2.3.0+）

- 支持多模态Embedding模型+图片向量化
- 图片要求长宽>=150px，否则忽略
- 支持手动添加图片索引
- 命中测试支持图文混搜
- 如果使用支持图像理解的总结模型，召回图片会传给模型
- **强烈建议使用向量检索**以实现图文混搜
- 修改Embedding模型或图片向量化开关将触发重新索引
- 切换配置时如确认一致可选择跳过重新索引（v2.4.0+）

## 知识看板（v2.5.0）

通过量化指标直观展现知识库的覆盖范围、使用频率与检索质量，帮助快速识别知识缺口、过时内容与冗余内容。

## RAG Prompt 模板

```
# 你的任务
基于我提供给你的知识库回答问题

# 我的问题
{question}

# 知识库段落
{paragraphs}
```

## Agentic RAG

高级实践：知识库分路由 + 工作流取片段 + 智能体推理

```
用户问题
    │
    ↓
[路由判断] → [知识库A工作流] → 找到？→ 返回
    │              │
    │              └→ 未找到 → [知识库B工作流] → ...
    │
    └→ [知识库C工作流] → ...
```

**案例**：AI 辅导员，学生咨询学校事务
